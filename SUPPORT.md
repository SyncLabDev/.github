# SYNC Lab Support

This document explains where different types of SYNC Lab support requests should be submitted.

---

## GitHub Issues

GitHub Issues are appropriate for:

- Reproducible bugs
- Repository-specific problems
- Documentation problems
- Feature requests
- Public open-source resource issues

Before opening an issue:

1. Confirm you are using a supported version.
2. Read the available documentation.
3. Search existing issues.
4. Check dependencies.
5. Check resource start order.
6. Check the client console.
7. Check the server console.
8. Reproduce the problem.
9. Test with conflicting resources disabled when practical.

Provide enough information for maintainers to reproduce the problem.

---

## Product Support

General product support may be more appropriate for:

- Installation assistance
- Server-specific configuration
- Paid resource support
- Compatibility questions
- Customer-related questions
- Order or purchase-related support

Use an official SYNC Lab support channel where available.

---

## What to Include

When requesting technical support, include:

- Resource name
- Resource version
- Framework
- Framework version
- FiveM artifact version
- Relevant dependencies
- Reproduction steps
- Client console errors
- Server console errors
- Screenshots or videos when useful

---

## Sensitive Information

Never post:

- Server passwords
- Database passwords
- Database connection strings
- API keys
- Discord bot tokens
- Private webhooks
- Tebex secrets
- License credentials
- SSH keys
- Production credentials

If sensitive credentials are exposed publicly, rotate them immediately.

---

## Unsupported Requests

SYNC Lab maintainers may redirect or close support requests that:

- Are unrelated to a SYNC Lab resource
- Do not provide enough information
- Duplicate existing reports
- Relate to unsupported or heavily modified versions
- Require debugging unrelated third-party resources
- Contain abusive or inappropriate behavior
